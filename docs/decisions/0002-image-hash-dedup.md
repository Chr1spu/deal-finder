# 0002 - Image-hash dedup: perceptual hash, compute-only for now

**Context:** Stage 2's roadmap calls for dedup logic beyond source ID, specifically an image hash, so the same physical item cross-posted across sources (eBay now, Depop next) can eventually be recognized as one item instead of two. Source-ID dedup already exists (`(source, source_id)` unique constraint, upsert in `ingest_saved_search`), but it can't catch a genuinely different listing on a different source for the same item. Only eBay is live right now; Depop doesn't exist yet, so there's no second source to actually test cross-source matching against.

**Decision:** Add a nullable `image_hash` column to `Listing` and compute it on ingest using a perceptual hash (`imagehash.phash` over Pillow), not an exact byte hash. Scope this stage to computing and storing the hash only, on first insert (or backfilling existing rows still missing one), not on every re-ingest. Do not build the actual cross-source duplicate-matching/merge logic yet, that lands with the Depop connector, once there's a second source to match against.

**Alternatives considered:** An exact hash (sha256 of the raw image bytes) was rejected: eBay and Depop each re-encode/resize photos independently, so the same physical photo would almost never produce identical bytes across sources, making an exact hash barely more useful than source-ID dedup already is. Building the full cross-source matching/merge pipeline now was rejected too, since there's nothing to test it against yet with only one source live, and it risks designing that logic around eBay's data shape alone rather than what Depop's actually turns out to look like.

**Consequences:** Adds two new dependencies, `imagehash` and `Pillow`. Ingest now makes one extra network call per new listing (fetching its primary image to hash), a failed fetch/decode is swallowed and leaves `image_hash` null rather than failing the whole ingest run. Existing eBay listings get backfilled with a hash the next time they're re-ingested and still missing one. The real dedup payoff (recognizing the same item across sources) doesn't exist yet and needs its own decision once Depop is built and there's real cross-source data to design against.
